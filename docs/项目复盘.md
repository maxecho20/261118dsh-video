## 读者值得复用的三个判断

1. **先定交付件，再定工具。** 口播需要可校对的原声、字幕和剪辑单。产品片需要可追溯的事实。MV 需要歌词、音乐和动作三者的时间关系。同一模型以三组不同证据做决定。
2. **实际执行能力要分开记。** Codex 帮编辑和写场景代码。Whisper 转录，librosa 取候选，FFmpeg 和 Remotion 等工具完成物理合成。iPhone 的三维场景和 MV 的像素／绘本动作使用了各自的专项实现。
3. **前置验证要针对最容易失败的瞬间。** 口播看首个角窗和一个术语，产品看第一处信息揭示，MV 看一次落脚和一次副歌转场。后续变更保留可对照版本。

## 开放版的边界

主要复刻动作是合成素材出片、用自己的素材替换、照提示词设计时间轴。初次短样无需模型密钥。正式片的全部资产与工程属于本地制作。本次只检查了口播音频窗口的相对对位，加上片尾转写核查，逐字听审仍有余量。MV 音轨多窗测量的零偏移证明了合成对位，个别歌词的实际句首、尾音仍应回听。对时长记录使用 MP4 探针，毫秒因容器音轨舍入略有差别。

Audio Separator、SOFA、Beat This! 仍为文档里列出的候选补件。本文不把它们计入三案已运行的工具。读者从 [快速开始](../README.md#先出一支片) 进入，再从 [三案提示词](../cases/README.md) 选一种替换自己的素材。
